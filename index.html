The Problem — Why Advertising Needs Agents

Before AdCP or ARTF, you need the broken world they're trying to fix.

BaselineLast updated: 2026-05-08

Part 1 — How Advertising Works Today

A quick map of the current stack before we explain what's broken in it.

Digital advertising today runs on a chain of platforms exchanging messages at machine speed. A DSP bids on impressions sourced through an SSP using the OpenRTB standard. In under 100ms the impression is auctioned, a winner is selected, and an ad serves. Billions of times per day. It works — but it was designed for machines following deterministic rules, not AI agents reasoning in natural language about campaign goals.

This works at massive scale. But it forces rich, strategic campaign intent into a compressed bid request structure. The nuance is lost, intermediaries compound fees, and only ~41% of spend reaches working media.

Part 2 — The Three Ceilings

Every existing buying model has a structural ceiling. These aren't execution failures — they're fundamental architectural limits.

①
Direct IO — Human Bandwidth

Agency negotiates directly with publisher. Rich data shared. Real deals closed. But a human trader can manage ~50 direct relationships. Not 500.

⚠ Scale is impossible. Manual throughput is the bottleneck.
②
Walled Garden APIs — Engineering ROI

Meta and Google have APIs with full data visibility. But a custom integration costs months of engineering — and that ROI only clears for two platforms.

⚠ Only viable for Meta & Google. The open internet is left out.
③
OpenRTB — Data Compression

Programmatic scales. But it compresses rich briefs ("align with sustainability, premium sports context") into a handful of fixed data fields. Publisher first-party richness is invisible.

⚠ ~41% working media. Strategic context is sacrificed for speed.

Part 3 — What AI Agents Change

AI agents can reason, plan multi-step tasks, and act autonomously. That breaks all three ceilings — but only if agents share a common protocol to communicate across platforms.

The shared protocols gap For agents to do this at scale, they need a shared language. Without it, every agent needs a custom integration per platform — the same fragmentation all over again, just at the agent layer. This is the gap AdCP and ARTF are designed to fill.

Under the Hood — Key Technical Concepts Explained Simply

When reading about ARTF and AAMP, four technical terms come up repeatedly. Here's what they actually mean — no engineering background required.

📦
Docker & Containerisation
Packaging software with everything it needs to run — like a shipping container that holds all its contents and can be dropped on any ship, truck, or train without repacking.
"Instead of installing software differently on every computer, you ship a pre-packed box that works the same everywhere."

🎛️
Kubernetes
The manager that automatically runs, scales, and restarts those containers across many servers. If one container crashes, Kubernetes spins up a new one. If traffic spikes, it launches more.
"It's like an airport operations centre — it doesn't fly the planes, it decides how many gates to open and reroutes when something breaks."
▶ Watch: Kubernetes explained
⚡
gRPC
A fast communication channel between computers. Standard web APIs (REST) are like sending letters — flexible but slow. gRPC is like a direct phone line — faster and more efficient, especially for high-volume machine-to-machine calls like bid requests.
"REST is a regular road. gRPC is a dedicated express lane. At 100 million bids per day, the express lane matters."

🗜️
Protocol Buffers
A compact data format that's smaller and faster to read than standard formats like JSON. Imagine sending a 10-page document vs. a compressed zip file — same information, much faster to transmit.
"JSON is readable English. Protocol Buffers is shorthand — 5x smaller, 5x faster to decode. At bid speed, that matters."

AdCP — Ad Context Protocol

What it is, how it works, the honest tradeoffs, and what it means for buyers and publishers.

UpdatedLast updated: 2026-05-06

Part 1 — What is AdCP?

Start here. This section covers the definition, what problem it actually solves, and why it was built now.

Ad Context Protocol (AdCP) is an open standard that gives AI agents a shared language to negotiate and transact advertising deals — agent to agent, without custom integrations per platform. Think of it as the "OpenRTB for agents": just as OpenRTB standardised how machines bid on impressions, AdCP standardises how agents brief, discover, negotiate, and buy.

Launch: October 15, 2025  |  Founding members: Scope3, Swivel, Triton Digital, Optable, and 15+ others  |  Governance: AgenticAdvertising.org (AAO), independent non-profit — no single company controls the spec

AdCP is built on top of Anthropic's Model Context Protocol (MCP) — the same infrastructure that lets AI assistants connect to external tools. This means any MCP-compatible AI assistant can, in theory, access any AdCP-compatible ad platform without custom integrations per platform.

Click to reveal
They communicate in natural language, collaborating as colleagues rather than just making structured API calls. A buyer agent can say "find me premium sports inventory in APAC Q3" and a seller agent responds with actual options.

Part 3 — How AdCP Works

The agent-to-agent flow, the four protocols, and what a live deal actually looks like end to end.

AdCP defines two roles: a Buyer Agent (representing an advertiser or agency) and a Seller Agent (representing a publisher or SSP). The protocol provides the shared language they use to communicate — so neither side needs to know the other's internal systems.

The communication is asynchronous by design. Unlike OpenRTB's sub-100ms auction, an AdCP deal negotiation might involve a human sign-off that takes 24 hours. This isn't a weakness — it reflects how premium deals actually work.

Part 4 — Publishers: AdCP or Build Your Own?

How publishers and SSPs actually implement AdCP — and the honest answer to whether a publisher needs to build their own agent protocol.

Direct answer: use AdCP, not a proprietary protocol. A publisher building a bespoke agent protocol means every buyer still needs a custom integration to talk to it — which is exactly the problem AdCP solves. The value of implementing AdCP as a seller is that any AdCP-compatible buyer agent (from any agency or advertiser) can immediately discover and transact with your inventory.

A publisher's implementation is called a Sales Agent — an agent that represents their inventory, pricing, and packaging to buyer agents. It receives natural language queries and responds with structured deal options.

Large Publishers

Build their own AdCP seller agent using the open spec. One-time engineering investment. Any buyer agent in the ecosystem can then query them directly. Full control over how inventory is presented and priced.

Mid-Tier Publishers

Rely on their SSP to build and operate a seller agent on their behalf. The SSP becomes the agent layer — publisher gets AdCP compatibility without engineering a custom implementation. PubMatic's AgenticOS is this model.

Small Publishers

Entirely dependent on SSP implementation. No direct AdCP involvement. The SSP aggregates small publisher inventory and presents it through a single seller agent — same as how they participate in programmatic today.

Part 5 — Honest Challenges & Tradeoffs

AdCP is genuinely promising — but the industry commentary overstates readiness and understates the unsolved problems. Here's what to watch.

A sharp question worth sitting with: Is this really progress, or are we just automating the IO model with better software? The structural comparison between AdCP and Direct IO is closer than AdCP advocates admit:

StepDirect IO (2015)AdCP (2026)
BriefAgency emails publisherBuyer agent messages seller agent
NegotiationAccount manager back-and-forthAgent-to-agent protocol exchange
ApprovalIO signed by both partiesHuman approval checkpoint
SetupTrafficking team creates line itemsAgents auto-create line items in ad server
AccountabilityIO = legal document⚠️ Legal framework for agent deals: TBD

The honest answer: AdCP is forward progress for the premium tier — deals that never worked in open auction programmatic. But it's not a revolution for the bottom 80% of the market. And it brings new problems that the IO model didn't have.

⚠ Line Item Proliferation at Machine Speed

If agents can negotiate thousands of direct deals autonomously, ad servers will be overwhelmed. Google Ad Manager and most ad servers weren't built for agent-generated deal volumes. A human trafficking team was a natural rate limiter. Agents aren't.

⚠ Legal and Contractual Accountability

When an AI agent agrees to a $500K deal, who signed it? Insertion orders have legal standing. Agent-executed transactions don't yet have clear contractual frameworks. "Embedded Human Judgment" addresses this philosophically but doesn't resolve the legal mechanics.

⚠ Price Discovery Without Auction Signals

Open auction gives you market price through competition. Direct AdCP deals require both sides to agree on a price without real-time competitive signals. Buyer agents negotiating in isolation could consistently overpay or underpay — and neither side would know.

⚠ Fraud Exposure is Front-Loaded

In programmatic, fraud detection happens at impression level — you catch it as budget is spent. In AdCP direct deals, you've committed budget before impressions run. If a seller misrepresents inventory, the exposure is realised before your detection layer sees it.

⚠ Agency Business Model Disruption

Agencies earn commission on spend and fees for campaign management. If AI agents negotiate and traffic directly, the human layer thins — and so does the justification for existing fee structures. This creates institutional resistance to adoption that has nothing to do with technology.

ARTF — Agentic RTB Framework

IAB Tech Lab's standard for running AI agent logic inside the bid stream — not alongside it.

UpdatedLast updated: 2026-05-08

Part 1 — What is ARTF?

ARTF is not a new auction format. It is infrastructure that lets agent decision logic run inside the real-time bid pipeline — without the latency cost of an external server call.

The Agentic RTB Framework (ARTF) v1.0 is an IAB Tech Lab standard released November 13, 2025. It solves a specific problem: AI agents need to make intelligent decisions on individual ad impressions in real time — but external AI calls are too slow for a sub-100ms bid window.

Release: November 13, 2025  |  Governing body: IAB Tech Lab  |  Reference implementation: Go (credited to Index Exchange Inc.)  |  Foundation: OpenRTB  |  AAMP role: Pillar 1 — Execution Infrastructure

The core innovation in one sentence Instead of calling an external AI service during a bid (adds 10–50ms network latency), ARTF packages the agent's logic in a container that runs inside the same server as the bid. No network hop. No latency penalty. Up to 90% latency reduction.
Flashcards — What is ARTF
What is the single core innovation of ARTF — and why does it matter for latency?
Click to reveal
Containerisation — running agent decision logic inside the same server as the bid rather than calling an external service. Eliminates the 10–50ms network round-trip that would otherwise blow the 100ms bid window. Latency reduction: up to 80–90%.
Core Innovation
What role does ARTF play within the broader AAMP umbrella initiative?
Click to reveal
ARTF is Pillar 1 of AAMP — the high-performance execution infrastructure layer. AAMP's Pillars 2 (shared protocols) and 3 (governance/Agent Registry) sit on top of this foundation. Without ARTF, agents can negotiate deals but can't optimise impressions at RTB speed.
AAMP Context
Why is ARTF described as backward-compatible — what specifically doesn't need to change?
Click to reveal
ARTF extends existing OpenRTB — it does not replace it. Existing bid request/response formats, ad servers, and auction mechanics continue unchanged. You add an RTBExtensionPoint call to your existing bidder; everything else keeps working exactly as before.
Architecture

Part 2 — Before and After ARTF

The latency problem that blocked agents from the bid stream — and how ARTF solves it structurally.

Traditional RTB requires the DSP to complete all decision logic before responding within 100ms. Any external API call — to a data provider, an ML model, a segment service — adds network latency. At scale, bid decisions must be pre-computed and deterministic, not dynamically reasoned per impression. Agents couldn't fit.

❌ Traditional RTB — External Agent Call Too Slow
Bid Request Arrives

Part 3 — Technical Architecture

The RTBExtensionPoint, what agents can actually do with it, and Index Exchange's role.

ARTF exposes a service called RTBExtensionPoint via gRPC. When a bid request arrives, the bid server calls RTBExtensionPoint with the full OpenRTB bid request. The agent analyses it and returns a set of mutations — proposed changes to how this impression should be handled.

What an ARTF Agent Can Propose

🤝
Deal Activation
Activate a specific private marketplace deal for this impression if it matches targeting criteria — determined in real time per impression
💰
Bid Price Adjustment
Bid shading — reduce or increase the bid based on predicted clearing price and this impression's specific value signals
🎯
Segment Addition
Add audience segments to the bid request in real time based on contextual analysis of the current bid context
📊
Viewability Signals
Attach predicted viewability metrics derived from page context and historical performance data for this placement

Uses Protocol Buffers for message serialisation — ~3–5x smaller and 5–10x faster than JSON/REST. Critical at millions of bid requests per second. A Web UI is included in the reference implementation for local testing without production infrastructure.

Part 4 — Honest Challenges

ARTF solves a real latency problem. But containerised agents inside bid servers introduce new operational and strategic risks worth understanding.

⚠ Deployment Complexity at Bid Scale

Running containers at bid server scale requires Kubernetes orchestration expertise. Most mid-tier SSPs and publishers don't have this in-house. The Go reference implementation lowers the bar, but production deployment at billions of impressions per day is still a serious engineering undertaking.

⚠ Agent Logic Auditability

When an AI container makes real-time bid decisions, who audits the logic? A deterministic bidding rule is easy to inspect. An ML model making sub-millisecond decisions is not. Advertisers and regulators will eventually ask what the agent did and why — and the answer needs to be legible at scale.

⚠ Errors Compound at Impression Scale

A bad bidding rule affects a campaign. A miscalibrated agent container affects millions of individual bids before anyone notices. The scale at which ARTF operates is also the scale at which mistakes propagate. Monitoring, rollback, and version control of agent containers become critical ops requirements.

SWOT — ARTF

▲ Strengths
  • Up to 90% latency reduction vs external agent calls
  • Backward-compatible with existing OpenRTB infrastructure
  • Go reference implementation (IX) — production-ready starting point
  • Per-impression AI decision-making at RTB speed
  • gRPC + Protocol Buffers — proven high-throughput stack
  • IAB Tech Lab governance — industry credibility
▼ Weaknesses
  • Significant deployment complexity (Kubernetes at bid scale)
  • Agent logic auditability is an unsolved UX problem
  • Limited to impression-level mutations — no campaign-level reasoning
  • Requires bid server operators to expose extension points
  • Container overhead is non-zero at very high QPS
▲ Opportunities
  • SSPs exposing RTBExtensionPoint become agent-ready infrastructure
  • Dynamic bid shading and deal activation at impression granularity
  • Supply-side decisioning — SSP-side agents, not just DSP-side
  • Real-time segment activation unlocks first-party data at scale
  • IX Go implementation: internal familiarity accelerates adoption
▼ Threats
  • Adoption requires SSPs/exchanges to modify core bidder infrastructure
  • A miscalibrated agent propagates errors at impression scale
  • AdCP direct deals could reduce the impression pool reaching ARTF
  • Walled gardens won't expose RTBExtensionPoint — open internet only

AAMP — The Big Picture

IAB Tech Lab's umbrella initiative announced Feb 26, 2026. The full operating system for agentic advertising.

UpdatedLast updated: 2026-05-11

What is AAMP?

Agentic Advertising Management Protocols (AAMP) is the umbrella initiative announced February 26, 2026 at Beet Retreat. It unifies all of IAB Tech Lab's agentic work under one coordinated roadmap — infrastructure + protocols + governance.

The Three Pillars of AAMP

Pillar 1 — High-Performance Delivery (Execution)

ARTF lives here — it's the engine under the hood. The core idea is simple: instead of an AI agent making a slow call to an external computer during a bid (which adds 20–50 milliseconds and blows the 100ms deadline), ARTF packages the agent's logic directly inside the same server that handles the bid. No round-trip. No latency penalty. Think of it like having a specialist colleague sitting next to you rather than calling them across the city every time you have a question.

The technical plumbing uses two tools: gRPC (a fast communication channel between computers — like a dedicated express lane vs. a regular road) and Protocol Buffers (a compact data format that travels faster than standard formats — like compressing a large file before emailing it). Both just mean the system moves data faster. You don't need to understand them to understand what ARTF does.

Pillar 2 — Shared Protocols (Standards)

Seven standardised "languages" that agents use to talk to each other. Each one replaces a specific manual process that exists today:

ProtocolWhat it replacesWhat agents can now do instead
Agentic AudiencesManual data onboardingShare audience signals privately, without exposing individual user IDs
Agentic Ad ObjectsCustom ad format specs per platformDefine ad formats once, works everywhere
Agentic DirectHuman-negotiated IO dealsAgents negotiate and book direct deals automatically
Agentic DealsManual deal ID setup in platformsAgents activate and manage PMP/PG deals without trafficking
Agentic RTBStatic bidding rulesAI logic runs inside the bid stream in real time (ARTF)
Agentic MobileSeparate mobile integrationsSame agent workflows work in mobile app environments
Agentic MeasurementPost-campaign manual reportingMeasurement signals flow automatically as part of each transaction

Pillar 3 — Trust and Transparency (Governance)

The Agent Registry — a public database of every AI agent operating in the ecosystem. Any agent transacting must be registered with: who built it, what version it is, and who is legally accountable if it does something wrong. This is the accountability layer that makes it safe to let agents spend real money autonomously. Launched March 1, 2026 in IAB Tools Portal.

Agentic Audiences (formerly UCP)

Donated by LiveRamp November 3, 2025. Standardises how agents exchange identity and contextual signals using dense vector embeddings (256–1024 dimensions) in a privacy-preserving, machine-readable format. Aligned with TCF and GPP privacy frameworks.

The Agent Registry

Every agent operating in the AAMP ecosystem must be registered in the Agent Registry: who built it, what version is running, what protocols it supports, and who is accountable if something goes wrong. Directly addresses fraud and accountability risks of autonomous agents spending real money.

AAMP 2.0 — What "Transaction-Ready" Actually Means

AdCP vs AAMP/ARTF — The Standards Battle

Competing or complementary? An honest breakdown as of May 2026, including the emerging consensus.

UpdatedLast updated: 2026-05-11

The Origin Story

When AdCP launched in October 2025, IAB Tech Lab CEO Anthony Katsur publicly questioned whether the industry needed "another industry trade group." Six weeks later, IAB Tech Lab released ARTF. Then in February 2026, AAMP was unveiled. IAB Tech Lab's framing: AAMP is not a reaction to AdCP — it's months of pre-existing work. The timing tells a story regardless.

Key Differences at a Glance

DimensionAdCPAAMP / IAB Tech Lab
GovernanceNeutral working group, 20+ companies, not vendor-ownedIAB Tech Lab — established non-profit since 2014, proven governance
Technical approachNative-to-agents, built on MCP, asynchronous, natural language firstExtends proven standards (OpenRTB, AdCOM), containerised real-time execution
ScopeDeal-level agent communication and transactionFull stack: infrastructure + protocols + governance
FoundationAnthropic's MCPOpenRTB, AdCOM, OpenDirect, Deals API
Adoption (May 2026)Early sell-side transactions via Swivel; Omnicom confirmed live buysBuyer/Seller SDKs released; Agent Registry live; ARTF v1.0 finalised

The Fragmentation Risk

Multiple competing protocols could fragment the ecosystem the way pre-OpenRTB programmatic was fragmented. If SSPs implement AdCP and DSPs implement AAMP protocols without interoperability, every agent needs custom integration per platform — recreating exactly the fragmentation both protocols are trying to solve.

IAB Australia and other voices are explicitly calling for AdCP agents to register with the AAMP Agent Registry and for both ecosystems to align.

The Emerging Consensus (May 2026)

The industry increasingly views these as complementary layers:

  • AAMP/ARTF handles high-performance execution infrastructure (impression-level, real-time)
  • AdCP handles deal-level agent negotiation language (asynchronous, campaign-level)

An agent built with AdCP could, in principle, use ARTF infrastructure to execute bids. Convergence is likely — the question is timeline and industry politics.
