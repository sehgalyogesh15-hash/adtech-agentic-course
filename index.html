Module 1 — The Problem: Why Advertising Needs Agents

Before understanding AdCP or ARTF, you need the broken world they're trying to fix.

BaselineLast updated: 2026-05-05

The Core Problem

Digital advertising runs on hundreds of disconnected platforms. A media buyer at an agency must log into a DSP, an SSP, a DMP, a measurement tool, a curation platform — each with its own interface, API format, and opaque pricing. Budgets leak into intermediary layers. No single agent can see the whole picture.

What Programmatic Looks Like Today

OpenRTB is the backbone — a standard for auctioning individual ad impressions in under 100ms. It works, but it was designed for machines following deterministic rules, not AI agents reasoning in natural language about campaign goals.

Key Concepts

TermDefinition
DSPDemand-Side Platform. Where advertisers/agencies buy ad inventory automatically.
SSPSupply-Side Platform. Where publishers sell ad inventory programmatically.
OpenRTBThe existing standard for real-time impression auctions. Works in <100ms per bid.
AI AgentAn autonomous AI that can reason, plan multi-step tasks, and take actions without human input per step.

Why 'Agentic' Matters Now

AI agents can reason about campaign briefs in natural language ("find women interested in ultramarathons on premium news sites"), discover inventory, negotiate deals, and optimise — all without a human clicking through dashboards. But for agents to work together across platforms, they need shared protocols. That's the gap AdCP, ARTF, and AAMP are designed to fill.

Future Role Impact

Media Planner — Your role shifts from manually building plans to briefing an AI agent in natural language. The agent does the discovery and packaging.

Ad Ops — Instead of managing platform UIs, you will manage agents — setting rules, auditing logs, and handling exceptions that agents escalate.

Ad Tech Engineer — Building MCP-compatible services and agent APIs becomes core work. OpenRTB knowledge remains essential as a foundation.

Checkpoint Questions

1. What does OpenRTB primarily standardise in advertising?
Real-time impression-level bidding auctions (sub-100ms)
2. What key capability do AI agents bring that traditional programmatic systems lack?
Natural language reasoning about campaign goals — interpreting briefs and acting autonomously without per-step human input

Module 2 — AdCP: Ad Context Protocol Explained

Launched Oct 15, 2025 by 20+ companies. Built on Anthropic's MCP. Live production buys confirmed April 2026.

UpdatedLast updated: 2026-05-06

What is AdCP?

Ad Context Protocol (AdCP) is an open standard that gives AI agents a shared language to communicate with ad platforms — and eventually with each other. Think of it as "OpenRTB for agents": just as OpenRTB standardised how machines bid on impressions, AdCP standardises how agents brief, discover, negotiate, and buy.

Launch date: October 15, 2025  |  Founding members: Yahoo, Optable, PubMatic, Scope3, Swivel, Triton Digital  |  Governance: AgenticAdvertising.org (AAO), independent non-profit

The Problem AdCP Solves

Without AdCP, every AI agent built by an agency or advertiser has to learn each platform's proprietary API separately. An agent that can buy on Yahoo can't talk to PubMatic without custom integration. AdCP creates a universal interface so any agent can plug into any compatible platform.

Built on Anthropic's MCP

AdCP is layered on top of the Model Context Protocol (MCP) — the same protocol Claude uses to connect to tools. Any AI assistant that supports MCP can, in theory, access advertising platforms directly through AdCP without custom integrations.

Unlike OpenRTB which handles sub-100ms impression auctions, AdCP operates asynchronously — a media buy negotiation might take minutes, hours, or require a human sign-off.

AdCP's Four Core Modules

ModuleStatusPurpose
Signals Activation ProtocolAvailable (2026 expansion)Discover, activate and manage audience data via natural language.
Media Buy ProtocolAvailableEnd-to-end campaign execution — verify publisher auth, modify budgets, adjust targeting, handle approvals.
Creative ProtocolAvailableBuild ad creatives, preview formats, explain rendering.
Curation ProtocolQ2 2026Standardise how inventory gets packaged and curated.

Adoption Reality (May 2026)

⚡ Major milestone — April 29, 2026 Omnicom CEO John Wren and Head of AI Paolo Yuvienco confirmed on Q1 2026 earnings call that Omnicom has already executed live media buys for several clients using an agent-to-agent framework built around AdCP. This is the most operationally specific statement any major holding company has made about agentic media buying — AdCP is no longer purely experimental.

PubMatic has transacted 250+ agentic deals on its platform since December 2025. The Trade Desk launched AI agents with Stagwell as first client, working alongside PubMatic, Scope3, and Magnite. The chicken-and-egg problem is beginning to resolve on the demand side.

AdCP governance note: now formally under AgenticAdvertising.org (AAO), an independent non-profit industry body — reinforcing its vendor-neutral positioning.

Future Role Impact

Media Buyer — AdCP means your AI assistant could query "find $50K of premium running content inventory in APAC" and get structured responses from all compatible SSPs at once.

Publisher / SSP — You build an AdCP-compatible "seller agent" that responds to natural language inventory requests. Your packaging becomes automated and accessible to AI buyers.

Checkpoint Questions

1. AdCP is built on top of which underlying protocol?
Model Context Protocol (MCP) by Anthropic
2. What is the main difference between AdCP and OpenRTB in terms of transaction speed?
AdCP is asynchronous — responses can take seconds or days, accommodating human approval. OpenRTB operates in under 100ms.

Module 3 — ARTF: Agentic RTB Framework Explained

Released Nov 13, 2025 by IAB Tech Lab. Built on OpenRTB. Cuts latency up to 90% via containerisation.

BaselineLast updated: 2026-05-05

What is ARTF?

The Agentic RTB Framework (ARTF) v1.0 is a standard that lets AI agents participate directly inside real-time bidding pipelines — without the latency of server-to-server round trips. The key innovation is containerisation.

Release date: November 13, 2025  |  Governing body: IAB Tech Lab  |  Reference implementation: Go (credited to Index Exchange Inc.)  |  Built on: OpenRTB

The Problem ARTF Solves

Traditional RTB requires multiple servers to exchange messages across the network (DSP → SSP → data provider → back). Each hop adds latency. At scale, this limits how much intelligent decision-making can happen per impression. Agent logic couldn't fit in the bid window.

The Containerisation Breakthrough

How containerisation works in ARTF Instead of calling an external API (which adds network latency), the agent's logic is packaged in a Docker-compatible container and runs inside the same server as the bid. Think of it like moving the brain into the body — no round-trips needed. Kubernetes can orchestrate these containers at scale across a fleet of bid servers.
ConceptExplanation
What is a container?Like a shipping container for software — packages all code and dependencies together. Runs inside one server.
Latency reductionARTF claims up to 80–90% latency reduction by running agent logic inside the same server as the bid.
Segment activationAgents can activate user segments based on bid request data in real time.
Backward compatibleExtends existing OpenRTB standards. Existing plumbing still works.

Technical Architecture

ARTF exposes an RTBExtensionPoint service via gRPC. Agents receive an OpenRTB bid request and return proposed mutations:

  • Deal activations
  • Bid price adjustments (bid shading)
  • Segment additions
  • Viewability metric additions

Also supports MCP and Agent-to-Agent (A2A) protocols. Uses Protocol Buffers for efficient message serialisation. A Web UI is available for local testing.

Index Exchange Involvement

Joshua Prismon, Chief Architect at Index Exchange, was quoted in the ARTF v1.0 press release. The Go reference implementation on GitHub is credited to Index Exchange Inc. IX has direct involvement in shaping this standard.

ARTF vs AdCP — The Key Difference

DimensionARTFAdCP
LayerImpression-level, inside RTB pipelineDeal/campaign-level, between agents
SpeedReal-time (<100ms)Asynchronous (seconds to days)
FoundationOpenRTBMCP
ScopeExecution infrastructureCommunication language
RelationshipComplementary — both now under AAMP umbrella

Future Role Impact

SSP / Exchange Engineer — You can expose ARTF-compatible agent extension points in your bidder. Third-party agents can enhance bids in real time without expensive integrations.

Yield Manager / Revenue Ops — ARTF enables per-impression sell-side decisioning at scale — AI can dynamically adjust floor prices, activate deals, and apply curation logic in real time.

Checkpoint Questions

1. What is the key performance advantage of ARTF's containerisation approach?
Eliminates server-to-server network hops, reducing latency by up to 90% by running agent logic inside the same server as the bid.
2. Which best describes the relationship between ARTF and AdCP?
ARTF handles real-time impression-level execution; AdCP handles deal-level agent communication — they are complementary, not competing.

Module 4 — AAMP: The Big Picture

IAB Tech Lab's umbrella initiative announced Feb 26, 2026. The full operating system for agentic advertising.

BaselineLast updated: 2026-05-05

What is AAMP?

Agentic Advertising Management Protocols (AAMP) is the umbrella initiative announced February 26, 2026 at Beet Retreat. It unifies all of IAB Tech Lab's agentic work under one coordinated roadmap — infrastructure + protocols + governance.

The Three Pillars of AAMP

Pillar 1 — High-Performance Delivery (Execution)

ARTF lives here. Containerised infrastructure for agents to operate inside real-time bidding at scale. Up to 90% latency reduction. Uses gRPC and Protocol Buffers for high-throughput communication.

Pillar 2 — Shared Protocols (Standards)

ProtocolBased onPurpose
Agentic Audiences (UCP)User Context Protocol (LiveRamp donation)Embedding-based audience signal exchange between agents
Agentic Ad ObjectsAdCOMStandardised ad object definitions across contexts
Agentic DirectOpenDirectAgents negotiate and transact direct deals
Agentic DealsDeals APIAgent-driven deal negotiation and activation
Agentic RTBOpenRTBARTF integration — agents inside the bid stream
Agentic MobileCloudX donationAgentic workflows in mobile app ecosystem
Agentic MeasurementOM SDK / Conversion APIMeasurement signals for agentic transactions

Pillar 3 — Trust and Transparency (Governance)

The Agent Registry — a public database of verified agents. Any agent transacting in the ecosystem must be registered. Launched March 1, 2026 in IAB Tools Portal.

Agentic Audiences (formerly UCP)

Donated by LiveRamp November 3, 2025. Standardises how agents exchange identity and contextual signals using dense vector embeddings (256–1024 dimensions) in a privacy-preserving, machine-readable format. Aligned with TCF and GPP privacy frameworks.

The Agent Registry

Every agent operating in the AAMP ecosystem must be registered in the Agent Registry: who built it, what version is running, what protocols it supports, and who is accountable if something goes wrong. Directly addresses fraud and accountability risks of autonomous agents spending real money.

2026 Roadmap Commitments

  • Open-source reference implementations of buyer and seller agents ✓ (released)
  • Neutral MCP reference server
  • Standardised agent profiles
  • Protocol Buffers and gRPC mappings for existing specifications
  • Trust, provenance, and measurement signals for transaction integrity

Future Role Impact

Ad Tech Platform (DSP/SSP) — Clear integration roadmap: implement Buyer Agent SDK (demand side) or Seller Agent SDK (supply side) from IAB Tech Lab's GitHub. Register your agents with the registry.

Privacy / Legal — Agentic Audiences uses embeddings aligned with TCF and GPP. Compliance requirements are encoded into the protocol layer, not bolted on.

Checkpoint Questions

1. What does AAMP's Agent Registry primarily address?
Accountability and transparency — knowing who built each agent, what version is running, and who is responsible for its actions.
2. Agentic Audiences (UCP) uses which technical approach to exchange audience signals in a privacy-preserving way?
Dense vector embeddings (256–1024 dimensions), aligned with TCF and GPP privacy frameworks.

Module 5 — AdCP vs AAMP/ARTF: The Standards Battle

Competing or complementary? An honest breakdown as of May 2026, including the emerging consensus.

UpdatedLast updated: 2026-05-06

The Origin Story

When AdCP launched in October 2025, IAB Tech Lab CEO Anthony Katsur publicly questioned whether the industry needed "another industry trade group." Six weeks later, IAB Tech Lab released ARTF. Then in February 2026, AAMP was unveiled. IAB Tech Lab's framing: AAMP is not a reaction to AdCP — it's months of pre-existing work. The timing tells a story regardless.

Key Differences at a Glance

DimensionAdCPAAMP / IAB Tech Lab
GovernanceNeutral working group, 20+ companies, not vendor-ownedIAB Tech Lab — established non-profit since 2014, proven governance
Technical approachNative-to-agents, built on MCP, asynchronous, natural language firstExtends proven standards (OpenRTB, AdCOM), containerised real-time execution
ScopeDeal-level agent communication and transactionFull stack: infrastructure + protocols + governance
FoundationAnthropic's MCPOpenRTB, AdCOM, OpenDirect, Deals API
Adoption (May 2026)Early sell-side transactions via Swivel; Omnicom confirmed live buysBuyer/Seller SDKs released; Agent Registry live; ARTF v1.0 finalised

The Fragmentation Risk

Multiple competing protocols could fragment the ecosystem the way pre-OpenRTB programmatic was fragmented. If SSPs implement AdCP and DSPs implement AAMP protocols without interoperability, every agent needs custom integration per platform — recreating exactly the fragmentation both protocols are trying to solve.

IAB Australia and other voices are explicitly calling for AdCP agents to register with the AAMP Agent Registry and for both ecosystems to align.

The Emerging Consensus (May 2026)

The industry increasingly views these as complementary layers:

  • AAMP/ARTF handles high-performance execution infrastructure (impression-level, real-time)
  • AdCP handles deal-level agent negotiation language (asynchronous, campaign-level)

An agent built with AdCP could, in principle, use ARTF infrastructure to execute bids. Convergence is likely — the question is timeline and industry politics.

Checkpoint Questions

1. Which statement best describes ARTF vs AdCP's approach?
ARTF extends proven existing standards with containerised real-time execution; AdCP is a native-to-agents standard built on MCP for asynchronous deal orchestration.
2. What is the main fragmentation risk if AdCP and AAMP don't converge?
Agents built for one ecosystem can't interoperate with platforms built for the other — recreating the fragmentation programmatic was meant to solve.
